# NovelForge「情节设定：手填 / 系统生成选项二选一」设计与改动方案（最终版）

## TL;DR（执行摘要）

> **实施状态（2026-06-19，分支 `feat/plot-setting-generation`）**：已按下列决策**全量实现并通过测试**（后端 TDD，全量回归 569 passed；前端 `tsc -b && vite build` 通过）。
> 用户决策落定：① 交互形态 = **建项目弹窗内联**「手填/生成」切换；② 范围 = **三阶段全做**（手填闭环 + 生成候选 + reroll/锁定）；③ 力量阶梯 = **MVP 即写入 `power_ranks` 表**（项目创建期的「阶梯注册」接缝，`rank_order` 由弱到强从 1 递增；非 canon 治理）。其余决策点（N=3/上限5、`max_tier=MID`、degraded 占位兜底、genre 生成枚举 8 项）按方案推荐值落地。
> 与原方案的唯一实质差异：§1/§3/§6/§9 中「力量阶梯 MVP 仅存 `meta_kv` 文本」已被决策 ③ 覆盖 —— 现改为在 `deps.py` 的 `ProjectRegistry._write_setting` 中直接 `INSERT INTO power_ranks`（文本散件仍走 `meta_kv`）。

让建项目时的「情节设定」既能**用户手填**、也能由系统**一次生成 N 个候选**供挑选 / 字段级编辑 / 单字段 reroll / 锁定再生成，全程贴合现有 Skill 契约 + 控制面 + 双模式 `human_gate` 治理。本方案以**真实代码现状**为准修正了初版三处致命错误：(1) 删除「力量阶梯走 `SeedProposal(fact_type='power_system')` 经 canon 治理投影到 `power_ranks` 表」这条错误链路，改为项目创建期的**阶梯注册**：`ProjectRegistry._write_setting` 直接 `INSERT INTO power_ranks`，不经过 `facts` / `fact_candidates` / `commit_canon`；(2) 正视 `SettingGenSkill` 是**全仓库首个无 DB Skill**，端点传 `:memory:` 占位 conn 满足 `SkillContext.conn` 的非 Optional 类型契约；(3) 修复 `power_system` 静默丢弃缺口（`create_project` handler 未透传，并非契约缺字段）。同时补齐了手填↔生成的完整交互闭环、单字段 reroll / 锁定字段的契约形状、degraded（fake provider）路径的确定性兜底、前后端契约镜像与测试覆盖。

## 1. 目标与范围

**问题陈述**：当前 `web/src/components/studio/CreateProjectModal.tsx` 已经能手填书名 + 题材下拉（`GENRE_OPTIONS`，9 项）+ 力量体系，且 `ProjectCreateRequest`（`novelforge/app/models.py:24`）**契约里本就有 `power_system` 字段**，前端也已发送它——但 `create_project` handler（`novelforge/app/api/projects.py:33`）只调 `registry.create(name=req.name, genre=req.genre)`，**handler 未透传 `power_system`**，导致它被静默丢弃。系统完全没有「生成情节设定候选供挑选」的能力。

**做什么**
- 定义结构化「情节设定」字段模型（题材 / 一句话设定 / 世界观 / 力量体系名 / 力量阶梯 / 主角 / 主线冲突 / 开篇钩子 / 目标读者 / 基调），每个字段都「可手填 + 可生成」。
- 新增**正向设定生成 Skill**（`SettingGenSkill`）+ **不依赖 project DB** 的端点 `POST /v1/projects/setup/suggest`，参照 `cold_start.py` 的「直建 Skill + fake provider 兜底 + `BudgetLedger` + `build_gateway`」装配，一次返回 N 个候选。
- 修复 `power_system` 丢弃缺口：`ProjectRegistry.create()` + `create_project` 把整套设定散件写入 `meta_kv`，并在 `ProjectResponse` 回显。
- 前端 `CreateProjectModal` 增加「手填 / 生成选项」模式切换 + 候选卡片挑选 + 字段级编辑 + 单字段 reroll + 锁定再生成。

**不做什么**
- **不把力量阶梯走 `facts` canon 治理**：力量阶梯在项目创建期直接注册到 `power_ranks` 表，属于表注册接缝，不是 canon fact 晋升。
- 不新增 World State 业务表、不改 `facts.fact_type` CHECK 白名单（`schema.sql:148`）、不改 `fact_candidates.status` CHECK（`schema.sql:501`）。
- 不引入候选 pairwise 评分漏斗（`candidate_judge`）——设定候选 MVP 用确定性去重即可。
- 不改 `commit_canon` / `PromotionPolicy` 治理内核，不开任何直写 `facts(status='canon')` 旁路。
- 不实现「设定→卷规划」串联向导（留作增强阶段，复用现成 `volume_plan` 端点）。
- 不把世界观/主角/基调「拆成 facts」（需 NER/三元组抽取 + entity 预建，建项目阶段 entity 尚不存在）——MVP 仅存 `meta_kv` 文本。

## 3. 设定字段模型

### 3.1 字段定义（每字段「可手填 + 可生成」）

| 字段 | key | 类型 | 落库去向 | 备注 |
|---|---|---|---|---|
| 书名 | `name` | str（必填） | `ProjectMeta.name` + `projects.json` | 仅手填，不生成 |
| 题材 | `genre` | enum（见 §3.5） | `ProjectMeta.genre` + `projects.json` | 单一真相源在 `ProjectMeta.genre`，**不双写 `meta_kv`** |
| 一句话设定 | `premise` | str | `meta_kv['premise']` | 世界观一句话梗概 |
| 世界观 | `world_setting` | str | `meta_kv['world_setting']` | 自由文本，MVP **不拆 facts** |
| 力量体系名 | `power_system` | str | `meta_kv['power_system']` | **当前 handler 丢弃，本方案修复** |
| 力量阶梯 | `power_ranks` | list[str]（有序） | `power_ranks` 表 | 项目创建期阶梯注册；`rank_order` 按弱→强从 1 递增，非 canon 治理 |
| 主角设定 | `protagonist` | str | `meta_kv['protagonist']` | MVP **不拆 facts** |
| 主线冲突 | `main_conflict` | str | `meta_kv['main_conflict']` | 核心爽点契约来源 |
| 开篇钩子 | `opening_hook` | str | `meta_kv['opening_hook']` | 第 1 章 hook 种子 |
| 目标读者 | `target_audience` | str（可选） | `meta_kv['target_audience']` | |
| 基调 | `tone` | str（可选） | `meta_kv['tone']` | MVP **不拆 facts** |

**落库分层原则**：
- **全部散件文本设定** → `meta_kv`（`db/connection.py:61` 的 `set_meta` 是现成接缝；建库时已用它写 `schema_version`/`tokenizer_version`）。
- **`genre` 单一真相源** = `ProjectMeta.genre` + `projects.json`，**不再写 `meta_kv`**（避免双真相源漂移）。
- **力量阶梯**（有序词表）→ `power_ranks` 表。**明确不走 `facts` canon 治理**（见 §2#A）。
- 世界观/主角/基调 MVP **不拆 facts**（拆 facts 需独立抽取 skill + entity 预建，列为增强项）。

### 3.2 后端 Pydantic 契约（`novelforge/app/models.py`，`# ── Projects ──` 段后新增）

```python
# ── Project Setup / Setting Generation ────────────────────────────────────────

class PlotSetting(BaseModel):
    """单份情节设定（手填或生成的候选；字段均可空便于局部填充）。"""
    genre: str = "xuanhuan"
    premise: Optional[str] = None              # 一句话设定
    world_setting: Optional[str] = None        # 世界观
    power_system: Optional[str] = None         # 力量体系名
    power_ranks: list[str] = Field(default_factory=list)   # 有序阶梯（MVP 写入 power_ranks 表）
    protagonist: Optional[str] = None
    main_conflict: Optional[str] = None
    opening_hook: Optional[str] = None
    target_audience: Optional[str] = None
    tone: Optional[str] = None

class SettingSuggestRequest(BaseModel):
    """生成 N 个情节设定候选。
    - locked + locked_fields：锁定字段作为条件生成前提（locked_fields 显式标注哪些 key 锁定）。
    - field 非空 = 只对单字段 reroll（此时服务端强制 n=1）。
    - avoid = 针对当前生成目标的历史值列表（去重）。"""
    name: Optional[str] = None
    genre: Optional[str] = None
    hints: Optional[str] = None                # 用户脑洞 / Braindump
    n: int = Field(default=3, ge=1, le=5)      # 越界由 Pydantic 拒绝（422）
    locked: Optional[PlotSetting] = None       # 已锁定字段值
    locked_fields: list[str] = Field(default_factory=list)  # 显式锁定的 key 集合
    field: Optional[str] = None                # 单字段 reroll 目标（如 'power_system'）
    avoid: list[str] = Field(default_factory=list)  # 该生成目标的历史值，避免重复

class SettingSuggestResponse(BaseModel):
    candidates: list[PlotSetting]
    degraded: bool = False                     # 无 key → fake provider，前端明示"示例数据"
    tier_used: Optional[str] = None            # generate_validated 实际档位

# ── 扩展现有 ProjectCreateRequest（保持向后兼容：保留 power_system / config_overrides）──
class ProjectCreateRequest(BaseModel):
    name: str
    genre: str = "xuanhuan"
    power_system: Optional[str] = None         # 既有字段，保留
    config_overrides: Optional[dict] = None    # 既有字段，保留
    setting: Optional[PlotSetting] = None       # 新增：最终确认的整套设定

# ── 扩展 ProjectResponse（回显，全部带默认值，向后兼容）──
class ProjectResponse(BaseModel):
    project_id: str
    name: str
    genre: str
    db_path: str
    created_at: str
    chapter_count: int = 0
    canon_fact_count: int = 0
    archived: bool = False
    power_system: Optional[str] = None         # 新增回显
    premise: Optional[str] = None              # 新增回显
```

> **`locked` vs `locked_fields` 的必要性**：`PlotSetting` 所有字段默认可空，单凭 `locked: PlotSetting` 无法区分「某字段值为 null 是因为未锁定/待生成」还是「锁定为空」。`locked_fields` 显式标注哪些 key 锁定，Skill 据此构造「保持 X 不变、只重生 Y」的 prompt。

### 3.3 DB 存储

- **不新增表、不改任何 CHECK**。
- 项目散件设定全部写 `meta_kv`，建库后由 `create_project` 调用 `set_meta`。

### 3.5 genre 枚举单一事实源

- 现状：`GENRE_OPTIONS`（`CreateProjectModal.tsx:20`）共 **9 个 value = 8 个真实题材（xuanhuan/xianxia/dushi/kehuan/lishi/wuxia/yanqing/xuanyi）+ 1 个 `default`（通用兜底）**。
- 问题：前端硬编码后端不可见；`SettingGenSkill` 做 enum 约束 / `DoDCheck('genre_valid')` 校验需要后端能拿到白名单。
- 方案：在后端新增单一常量 `GENRE_VALUES: tuple[str,...]`（建议放 `novelforge/app/models.py` 或 `config.py`），`SettingGenSkill` 与端点 import 它；前端仍用 `GENRE_OPTIONS`（label+value），但 value 集合必须与后端常量一致（加一行注释互指）。
- **`default` 不纳入生成 enum**（它是兜底通用项，不应作为模型产出的「题材」）；生成时 enum 约束到 8 个真实题材，但 `genre_valid` 校验白名单 = 全部 9 项（含 `default`，因为手填路径允许 `default`）。

## 4. 生成能力（后端）：`SettingGenSkill` + `POST /v1/projects/setup/suggest`

### 4.1 新 Skill：`novelforge/skills/setting_gen_skill.py`

**定位**：**全仓库首个无 DB Skill**——在「建项目之前」运行，没有 project DB。`run()` 严格不读 `ctx.conn`（由单测断言保证，见 §7）。

```python
_CONTRACT = SkillContract(
    name="setting_gen",
    version="1.0",
    trigger=SkillTrigger.MANUAL,
    model_tier=ModelTier.MID,                  # 默认单档（探索阶段不升 STRONG，见 §2#E）
    inputs=IOSpec(["name", "genre", "hints", "n", "locked", "locked_fields", "field", "avoid"],

    outputs=IOSpec(["candidates", "tier_used"], "N 份 PlotSetting 候选 + 实际档位"),
    dod=[
        DoDCheck("has_candidates", "至少产出 1 个候选"),
        DoDCheck("genre_valid", "每个候选 genre 在白名单内（含 default）"),
        DoDCheck("min_fields", "每个候选 premise/protagonist/main_conflict 非空"),
    ],
    read_scopes=["workspace"],                  # 文档性声明：本 skill 不读 DB（运行时不强制）
    write_scopes=["workspace"],
    cache_prefix_keys=["locked", "genre"],      # 文档性占位（运行时不驱动缓存，见下）
```

**`run()` 黑板写回契约（必须显式，否则端点取不到）**：

```python
def run(self, ctx: SkillContext) -> SkillResult:
    # 关键自律：全程不引用 ctx.conn
    ws = ctx.workspace
    n = max(1, min(5, int(ws.get("n") or 3)))
    field = ws.get("field")
    if field:
        n = 1                                   # 单字段 reroll 强制单候选
    # ... 组 prompt（stable 前缀 = locked + genre 枚举说明）...

    from ..control_plane.llm.provider import CacheHint, Message
    from ..control_plane.llm.tiers import ModelTier
    result = ctx.llm.generate_validated(
        ModelTier.MID,
        [Message(role="user", content=user_msg)],
        parse=lambda txt: _parse_candidates(txt, n=n, field=field,
                                            locked=ws.get("locked"),
                                            avoid=ws.get("avoid") or []),
        system=_SYSTEM,
        max_tokens=4096,
        temperature=1.0,
        cache_hint=CacheHint(user_prefix_chars=len(stable)) if stable else None,
        max_tier=ModelTier.MID,                 # 默认单档；升档可由调用方放宽
    )
    candidates = result.value or [_fallback_candidate(ws)]   # value=None → 确定性兜底 ≥1 条
    # ── 必须显式写回黑板 ──
    ctx.workspace["candidates"] = candidates    # list[dict]，端点再 PlotSetting(**c)
    ctx.workspace["tier_used"] = result.tier_used

    genre_ok = all(c.get("genre") in GENRE_VALUES for c in candidates)
    dod = [
        DoDOutcome("has_candidates", passed=bool(candidates)),
        DoDOutcome("genre_valid", passed=genre_ok),
        DoDOutcome("min_fields",
                   passed=all(c.get("premise") and c.get("protagonist")
                              and c.get("main_conflict") for c in candidates)),
    ]
    return SkillResult(skill_name="setting_gen", ok=bool(candidates),
                       payload={"candidates": candidates}, dod_outcomes=dod,
                       usage_summary=f"tier={result.tier_used} esc={result.escalated}")
```

**`_fallback_candidate(ws)`**（degraded / parse 全失败的确定性兜底）：返回 1 条 `dict`，`genre` 取 `ws['genre'] if in GENRE_VALUES else 'default'`，其余字段填可读占位（如 `premise="（示例）请配置 API key 后生成，或手动填写"`），**保证 genre 合法、字段非脏**，前端可直接渲染、可建项目。

**`_SYSTEM` 提示词要点**：
- 一次输出含 N 个对象的 ```settings JSON 数组（解析复刻 `volume_plan_skill._parse_plans` 的 ```块 + 逐步补符号抢救）。
- **多样性约束（落成可执行判据，见 `_parse_candidates`）**：硬性要求「N 个候选的 `power_system` 名两两不同、`main_conflict` 类型彼此不同」。注：gateway **不透传 `n`/penalty 参数**（`gateway.py:53` 单次单条），多样性只能靠 prompt 约束 + reroll 的 avoid 清单，**不绑定任何 provider 特性**。
- **条件生成**：若给 `locked` + `locked_fields`，把 `locked_fields` 列出的字段值作为「必须保持一致的前提」塞入 prompt，只生成未锁定字段。
- **单字段 reroll**：若给 `field`，只重生成该字段，其余字段照搬 `locked`；`avoid` 列出该字段历史值，要求「不得与以下重复」。`power_ranks` 这种 list 字段 reroll = 整列重出。
- `genre` enum 约束到 8 个真实题材（见 §3.5）；`power_ranks` 要求有序数组。

**`_parse_candidates(text, n, field, locked, avoid)` 三级 fallback + 机器判据**（抄 `_parse_plans`）：
1. 提取 ```settings 块 → 逐步补 `]`/`}]`/`"}]` 抢救 → `json.loads`。
2. 过滤非 dict、genre 非法项；每条 clamp 字段长度。
3. **多样性硬校验**：若是首屏多候选（`field` 为空），要求 `power_system` 名两两不同 + `main_conflict` 关键词不重合，否则视为不合格**返回 None**（触发 `generate_validated` 升档 / 最终兜底）——避免「同质但格式合法」蒙混过关。
4. **最低字段完整度**：`premise`/`protagonist`/`main_conflict` 任一为空视为不合格。
5. **单字段 reroll**（`field` 非空）：只取该字段值，与 `locked` 合并成 1 条完整 `PlotSetting` dict；若新值落在 `avoid` 中则判不合格（要求 reroll 出不同值）。
6. 全部合格才返回 `list[dict]`，否则返回 `None`。

> **CacheHint / cache_prefix_keys 说明**：`cache_prefix_keys` 是 `SkillContract` 纯文档字段（`skill_contract.py:49`，运行时不驱动缓存）。真正吃缓存靠 `generate_validated(cache_hint=CacheHint(user_prefix_chars=len(stable)))`。但 `FakeProvider.capabilities` 返回 `supports_cache=False`（`fake_provider.py:65`），**缓存收益只在真 provider（anthropic / deepseek_anthropic）生效**，degraded 下无效。

**注册**（保持一致性）：`skills/__init__.py` 加 `from .setting_gen_skill import SettingGenSkill`、`reg.register(SettingGenSkill())`、`__all__`。端点走直建 Skill 路线，注册非必需但建议。

- *验收*：无 key 时 `degraded=True` 返回 **≥1 条占位**（genre 合法、字段非脏）不报 500；有 key（anthropic）时一次返回 3 个 genre 合法、`power_system` 名两两不同、`premise/protagonist/main_conflict` 非空的候选；挑选后可确认建项目。

**MVP-3（精修交互）**
- 字段级 ✨ reroll（`field`+`avoid`+`n=1`）+ 🔒 锁定再生成（`locked`+`locked_fields`）；`power_ranks` 编辑 + 整列 reroll。
- *验收*：锁定主角后「重生其余」主角不变；单字段 reroll 产出值不在 `avoid` 中且其余字段不变。

**增强**
- 升 STRONG 可选开关 + `tier_used` 前端展示（仅 anthropic provider 有质量增益，见 §2#E）。
- 力量阶梯注册增强：补充编辑/补录 API、冲突校验与导入工具；当前 MVP 已在项目创建期直接 `INSERT INTO power_ranks(system_name, rank_name, rank_order)`，它是**表注册**而非 facts canon 治理。
- 世界观/主角/基调拆 facts（需独立抽取 skill + entity 预建）。
- 「设定→卷规划」冷启动向导（复用现成 `volume_plan` 端点）。
- 👍/👎 偏好迭代，保留/拒绝清单回喂下一轮条件生成。

## 9. 风险与取舍

- **`power_ranks` 表落库断链**（已修正）：不再让力量阶梯走 `power_system` fact 的 canon 投影链路；项目创建期直接注册 `power_ranks`。`power_system` fact 仍只表示角色境界变化，继续强依赖已注册 rank + 已存在 entity。
- **无 DB Skill 是新模式**（已正视）：`SkillContext.conn` 非 Optional，端点传 `:memory:` 占位 conn 满足契约；`read_scopes` 是纯文档字段无运行时强制，真正保证靠 `run()` 自律 + 单测断言不碰 `ctx.conn`。这是全仓库唯一允许此模式的 skill，代码加注释防他人误用。
- **degraded（fake provider）质量**（已修正）：默认 `FakeProvider()` 只回显、产不出合法 JSON，`generate_validated` 必返回 `value=None`→**确定性占位兜底**。前端 `degraded=True` 明示「示例数据」。本地演示多候选需显式注入产 JSON 的 `FakeProvider(factory=...)`。
- **DeepSeek 升档无增益**（已修正）：`_model_map` 把 mid==strong（`factory.py:18-22`），`MID→STRONG` 升档=同 model 重跑只多花钱。探索阶段默认 `max_tier=MID`（单档）；升 STRONG 仅在 anthropic provider 有意义。
- **单次 N 候选易同质化** vs **循环 N 次成本 O(N)**：采混合——首屏单次数组（省钱、可吃缓存），单条 reroll 才走条件生成 + avoid（O(1) 增量）。同质化用 `_parse_candidates` 机器判据（power_system 名两两不同 + main_conflict 不重合）拦截，不合格触发升档/兜底。N 上限 5。
- **成本/延迟**：端点配**独立小预算 ledger**（`max_tokens=20000, max_usd=0.20`），不共享章节预算；`n`/`max_tokens` 硬上限；前端生成/重生按钮 in-flight 节流。
- **多样性论证不绑 provider**：gateway 不透传 `n`/penalty，多样性只能靠 prompt 约束 + reroll avoid，与 Claude/DeepSeek 具体特性无关。
- **路由顺序脆弱性**：`/setup/suggest` 静态段声明在 `/{project_id}` 动态路由之前，加注释；未来若加 `POST /{project_id}/...` 须保持此顺序。
- **MVP 切分**：MVP-1（修缺口）作为独立可交付 PR 先落地，与生成能力（MVP-2/3）解耦，避免被复杂度裹挟。

## 10. 需要用户拍板的决策点

1. **内联 vs 独立向导页**：在 `CreateProjectModal` 内联「手填/生成」切换（改动小、推荐），还是新建独立「设定向导」页（分步级联，体验更丰富但工作量大）？
2. **候选数量 N**：默认 3、上限 5（推荐）？还是对齐章节 `n_candidates` 的 1~3 口径？`n` 越界明确为 **Pydantic 422 拒绝**（非 clamp），是否接受？
3. **力量阶梯落库**：已按用户决策提前到 MVP，项目创建期直接写 `power_ranks` 表；后续只需决定是否增加编辑/补录 API 与冲突校验。
4. **ModelTier**：探索阶段默认 `max_tier=MID` 单档（推荐，省钱；DeepSeek 下升档本就无增益）。是否要在 anthropic provider 下开「升 STRONG」可选开关？
5. **degraded 演示质量**：无 key 时返回「1 条占位 + degraded 提示」（推荐，零额外代码），还是注入产 JSON 的 `FakeProvider(factory)` 以演示真·多候选（需额外 fixture）？
6. **题材放宽**：`genre` 生成时 enum 约束到 **8 个真实题材**（排除 `default` 兜底），手填路径允许全部 9 项（含 `default`）。是否接受这一区分？还是允许生成/自由填新题材（需放宽 `GENRE_OPTIONS`，并影响 genre→节拍模板映射）？
