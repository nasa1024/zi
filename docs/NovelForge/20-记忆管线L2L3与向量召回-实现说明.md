# 20 · 记忆管线 L2/L3 与向量召回 — 实现说明

> 补齐 §06 记忆管线里此前仅为存根的两块 + MVP2 推迟的向量召回：
> **L2 场景聚合**、**L3 事件驱动 canon 提案**、**embedding/RRF 向量召回**。
> 全部默认关闭，开启后亦不破坏既有 561 项测试与召回主路。

## TL;DR

| 能力 | §06 出处 | 此前状态 | 现状 | 开关 |
|---|---|---|---|---|
| L2 场景聚合 | §06.2.2 | `PipelineManager.run_l2` 空存根、无人调用 | 每章切场景→FAST 摘要→写 `l2_scenes`，按"每 N 章 / 卷末"触发，接入 settle | `memory.enable_l2`（默认 False） |
| L3 事件驱动 | §06.2.3 / §06.3.3 | `run_l3_if_needed` 空存根 | 确定性扫 canon 信号→有信号才 LLM 归一化→证据校验→去重→入 staging（proposed，人审兜底） | `memory.enable_l3`（默认 False） |
| 向量召回 | §06.4.3 | 全仓库零 embedding/RRF | 离线 HashEmbedder + `scene_vec` 暴力余弦 + 词法路 RRF 融合，注入"相似桥段"通道 | `recall.enable_vector`（默认 False） |

**设计立场**：向量召回是"增强、非主路、可关闭"（硬原则 4）；关闭后结构化 SQL + FTS5 主路完全不变。所有 LLM 调用走现有 `LLMGateway`/`BudgetLedger`，离线 FakeProvider 可跑、无网络、无新第三方依赖。

## 1. 数据契约（v15）

新增迁移 `db/migrations/v15.py`，`SCHEMA_VERSION` 升至 `"15"`，并写入 `schema.sql` 基线：

```sql
CREATE TABLE scene_vec (
    scene_id  TEXT PRIMARY KEY,   -- = l2_scenes.id
    chapter   INTEGER NOT NULL,   -- 冗余章号，便于 as-of(chapter<=) 过滤
    dim       INTEGER NOT NULL,
    vec_json  TEXT NOT NULL,      -- JSON float 数组（回退暴力检索）
    model TEXT, version TEXT, created_at TEXT
);
```

- `l2_scenes`（已存在）承载场景文本 + 摘要 + embedding 元数据列；`scene_vec` 单独存向量本体。
- **为何不用 sqlite-vec**：它是可选加载扩展、当前环境未安装。`scene_vec` + 暴力余弦在单库场景量（百~数千）下足够；sqlite-vec 可作未来快路替换，**不改本表契约与调用方签名**。

## 2. 模块布局

```
novelforge/memory/
  embedding.py      Embedder 协议 + HashEmbedder（特征哈希，离线确定性）+ cosine
  vector_store.py   SceneVectorStore：scene_vec 存取 + as-of 暴力余弦检索
  l2_aggregate.py   split_scenes / aggregate_chapter_scenes / run_l2_window / should_run_l2
  l3_events.py      scan_canon_signals / extract_canon_events（CANON_TYPES 四类）
  recall.py         +similar_scenes 字段、rrf_fuse、search_similar_scenes、gather_hard_context 向量参数
```

## 3. L2 场景聚合（§06.2.2）

- **切分纯确定性**（`split_scenes`）：优先按分隔线（`***`/`———`/`※`…）切；无分隔线按空行分段；过短片段并入相邻块；超 `l2_max_scenes_per_chapter` 的尾部并入末块（不丢内容）。零 LLM、可复现。
- **摘要**：每场景一次 FAST 档摘要（≤80 字）；无 gateway/失败时降级为截断原文当摘要，仍可建语料/向量。
- **触发**（`should_run_l2`）：每 `l2_every_n_chapters` 章（默认 4）**或**卷末（`volumes.end_chapter`）。触发时聚合当前章（用手头正文）+ 回填本窗口 `[chapter-N+1, chapter)` 中尚无 L2 的章（从 L0 读回），**单次处理量有界 ≤N 章**。
- **幂等**：按 `(chapter, scene_seq)` upsert，复跑不产生重复行。

## 4. L3 事件驱动 canon 提案（§06.2.3 + §06.3.3）

定位为出稿期 LLM 抽取（`ChapterDraftSkill`→proposals）之外的**异步安全网**：

1. **确定性扫信号**（`scan_canon_signals`，保不漏）：`world_rule`/`foreshadowing`/`constraint` 用词表，`new_entity` 用书名号/引号专名且不在已知实体集。
2. **有信号才调一次 LLM 归一化**为结构化原子（绝大多数章零 LLM 成本）。
3. **证据后验校验**（§06.3.1）：原子的 `evidence` 必须是正文连续子串，否则丢弃（防幻觉）。
4. **去重**：与本章既有候选按 `(fact_type, entity)` 去重，避免与出稿期抽取重复入库。
5. 产出 `BibleChangeProposal` 形状 dict（`op=add`）→ `_proposals_to_candidates` 入 staging（`proposed`，**绝不直接 commit**，走人审兜底——原则 2）。

## 5. 向量召回 + RRF（§06.4.3 / §06.4.5）

- **embedding（可插拔，配置驱动）**：`build_embedder(cfg.memory)` 是唯一构造入口，按 `embedding_provider` 分发：
  - `"hash"`（默认）→ `HashEmbedder` 特征哈希（单汉字 + 汉字 bigram + ASCII 词 → md5 分桶 + 符号位 → tf 加权 → L2 归一）。离线、确定性、跨进程可复现、零依赖。
  - `"openai"` → `OpenAIEmbedder` 调 **OpenAI 兼容 `/v1/embeddings`**（OpenAI / DeepSeek / vLLM / 任意兼容端点）；维度由模型决定（首次调用后发现），client 惰性构造（构造 embedder 不触发 `import openai`）。
  - 未知 provider → 回退 hash（绝不因配置笔误而崩）。
  `name/version` 落 `scene_vec`（hash→`hash/v1`；openai→`openai/<模型 id>`），换模型时旧维度向量被检索侧自动跳过。换本地神经模型（bge-m3 等）只需再实现一个 `Embedder` 协议类并在 `build_embedder` 加一个分支。
- **检索**：`SceneVectorStore.search` 取 `chapter<=as_of` 的场景向量做暴力余弦（防剧透语义与硬召回一致）。
- **RRF**（`rrf_fuse`，k=60，只用排名）：融合**向量路**与**词法路**（场景摘要+原文上的 query 分词命中排名）两条 scene_id 排名列表，产出"相似桥段"。
- **注入**：`gather_hard_context(..., embedder, enable_vector, scene_query)` 写 `RecallPack.similar_scenes`，在**动态层**（cache 断点之后，不污染稳定前缀）渲染"## 相似历史桥段"通道。失败静默降级，不影响硬召回。

## 6. 接线（orchestrator settle 阶段）

`control_plane/orchestrator.py`：

- **召回侧**：`generate_chapter` 的 RECALL 阶段在 `enable_vector` 时构建 embedder 并把向量参数传入 `gather_hard_context`，相似桥段随动态上下文进起草 prompt。
- **结算侧**：settle 块新增 `_step("l2_aggregate")` / `_step("l3_events")`，受 `memory.enable_l2/enable_l3` 门控；与既有 pacing/summary/foreshadow 步骤一样**各自降级互不阻塞**（正文已落袋，记忆步失败只标 degraded 不丢章）。

## 8. 默认值与开启建议

| 配置 | 默认 | 生产建议 |
|---|---|---|
| `memory.enable_l2` | False | 需"查相似桥段"时开；配 `enable_vector` 才有召回价值 |
| `memory.l2_every_n_chapters` | 4 | 3–5；卷末必触发 |
| `memory.enable_l3` | False | 想要 canon 抽取安全网时开；产物进人审队列 |
| `recall.enable_vector` | False | 开则按 `embedding_provider` 构建 embedder 并注入相似桥段 |
| `memory.embedding_dim` | 256 | hash 专用；128–512，越大碰撞越少、越慢 |
| `memory.embedding_provider` | `"hash"` | 离线默认；接第三方设 `"openai"` |
| `memory.embedding_model` | `text-embedding-3-small` | openai provider 的模型 id（维度由模型决定） |
| `memory.embedding_base_url` / `embedding_api_key` | None | openai 兼容端点与密钥；缺省回退 LLM 的 base_url/key |

**环境变量（API 层，无需改代码即可切第三方）**：`NOVELFORGE_EMBEDDING_PROVIDER=openai`、`NOVELFORGE_EMBEDDING_MODEL`、`NOVELFORGE_EMBEDDING_BASE_URL`、`NOVELFORGE_EMBEDDING_API_KEY`（后两者缺省回退 `NOVELFORGE_API_KEY`/`DEEPSEEK_API_KEY` 与 LLM base_url）。由 `app/api/orchestrator.py:_apply_embedding_env` 注入 `cfg.memory`。

## 9. 已知边界 / 未来项

- 默认 HashEmbedder 是词形特征哈希，非语义模型：近义不同词的召回弱于神经 embedding。需要更强语义时，已可**配置驱动**切到 `embedding_provider="openai"`（OpenAI 兼容 `/v1/embeddings`，含云端 text-embedding-3-* 或本地 vLLM/Ollama 暴露的 bge-m3 等）；纯本地进程内模型（sentence-transformers 直跑）则再加一个 `Embedder` 协议实现 + `build_embedder` 分支即可（契约与 `scene_vec` 不变）。
- OpenAI embedder 走外网/外部服务，受网络与配额影响；切换模型后维度变化的旧向量会被检索侧按 `dim` 跳过，需要时可重嵌（`scene_vec` 存 `model/version` 便于识别）。`openai` 包为可选运行时依赖（未装时仅在实际 embed 时报清晰错误）。
- `scene_vec` 暴力余弦在万级场景以上需换 sqlite-vec(vec0) KNN（已预留替换点）。
- L2 回填仅覆盖触发时的"近 N 章窗口"；对存量长篇的一次性全量回填可另用 `run_l2_window(up_to=当前章)`（未接 API，按需）。
- 旧 `memory/pipeline_manager.py` 的 L1 字符串匹配 + L2/L3 存根仍在但不被 orchestrator 使用；真实 L2/L3 走本文新模块。
